# PR Security Gate

Reusable workflow that gates pull requests on newly-introduced vulnerable dependencies (via Dependabot/GitHub Advisory Database) and Semgrep findings. Runs on every PR open/sync, posts a sticky comment with findings, and fails when high-severity issues are detected.

**Source:** `.github/workflows/pr-security-gate.yml`  
(Hand-authored — not generated by dotgithub.)

## Features

- **Dependency scanning** via `actions/dependency-review-action` — detects vulnerable deps added by the PR
- **Semgrep scanning** — reads results from the org's `gd-dodge` app (SARIF uploads to code scanning), with CLI fallback
- **Sticky PR comment** — one comment per PR, updated on each push
- **Configurable thresholds** — default: block on `high`/`critical` deps or `error`-level Semgrep findings
- **Dry-run mode** — set `block: false` to report without failing the check

## Inputs

| Input | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `runner_group` | string | no | `7219-mscicdrunners` | Self-hosted runner group for all jobs |
| `dep_fail_severity` | string | no | `high` | Minimum vulnerability severity to fail the check (`low`, `moderate`, `high`, `critical`) |
| `semgrep_fail_severity` | string | no | `error` | Minimum Semgrep severity to fail the check (`note`, `warning`, `error`) |
| `block` | boolean | no | `true` | Whether to fail the check when thresholds are exceeded (set `false` for dry-run) |
| `dodge_wait_minutes` | number | no | `15` | Minutes to wait for `semgrep-dodge` check before falling back to CLI |
| `semgrep_fallback_config` | string | no | `p/default` | Semgrep config to use when falling back to CLI (e.g. `p/default`, `p/security-audit`) |

## Permissions

The workflow requires these permissions on the caller:

```yaml
permissions:
  contents: read
  pull-requests: write
  security-events: read
  checks: read
  id-token: write
```

## How It Works

### 1. Dependency Review (`deps` job)

Runs `actions/dependency-review-action` with `warn-only: true` (so it never fails itself). The action compares the PR's manifest/lockfile changes against GitHub's Advisory Database and exports a `vulnerable-changes` JSON output. This covers npm, including marketing-cds's per-package lockfiles.

### 2. Semgrep Scan (`semgrep` job)

**Primary path (Dodge):**  
Polls for the `semgrep-dodge` check run (the org's `gd-dodge` app) for up to `dodge_wait_minutes`. When it completes, queries the code-scanning API for `Semgrep OSS` alerts on the PR ref vs. the base ref. Alert numbers are fingerprint-stable, so `new = PR alerts - base alerts`.

**Fallback path (CLI):**  
If Dodge doesn't complete in time, installs `semgrep==1.178.0` via JFrog OIDC (Artifactory PyPI) and runs `semgrep scan --config <fallback_config> --baseline-commit <base_sha> --json`. The PR comment notes that the fallback was used, since fallback rules (`p/default`) differ from Dodge's `godaddy.*` ruleset.

### 3. Report (`report` job)

Builds one markdown comment with:
- Status header (✅ / ❌)
- Dependency vulnerabilities table (package, version, advisory, severity, fixed-in)
- Semgrep findings table (rule, file:line link to PR diff, severity, message)
- "How to Fix" footer (`# nosemgrep: <rule>` suppression, Dependabot PR links)

**Comment upsert:** finds the existing comment by marker `<!-- pr-security-gate -->` and updates it; creates one if none exists. If the PR is now clean, the comment updates to "✅ No security issues found."

**Dependabot PRs:** `GITHUB_TOKEN` is read-only on Dependabot PRs, so the comment upsert is skipped. The step summary and check status still surface the results.

**Check status:** `core.setFailed` when `block: true` and any finding meets the threshold (dep ≥ `dep_fail_severity` or Semgrep ≥ `semgrep_fail_severity`).

## Usage

### Basic (default thresholds)

```yaml
name: PR Security Gate
on:
  pull_request:
    branches: [main]
    types: [opened, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: write
  security-events: read
  checks: read
  id-token: write

concurrency:
  group: pr-security-gate-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  gate:
    uses: gdcorp-actions/gd-pr-gate/.github/workflows/gate.yml@v1
    with:
      runner_group: 7219-mscicdrunners
```

### Custom thresholds

```yaml
jobs:
  gate:
    uses: gdcorp-actions/gd-pr-gate/.github/workflows/gate.yml@v1
    with:
      runner_group: 7219-mscicdrunners2
      dep_fail_severity: moderate      # stricter: block on moderate and above
      semgrep_fail_severity: warning   # stricter: block on warning and above
```

### Dry-run mode

```yaml
jobs:
  gate:
    uses: gdcorp-actions/gd-pr-gate/.github/workflows/gate.yml@v1
    with:
      runner_group: 7219-mscicdrunners
      block: false  # report only, never fail the check
```

## Making the Check Required

After verifying the gate works on one or two PRs, make the `gate / report` check required in branch protection:

1. **Via UI:** Repo **Settings → Branches → main** branch rule → **Status checks** → add `gate / report`.
2. **Via API:**
   ```bash
   gh api -X PATCH repos/{owner}/{repo}/branches/main/protection \
     -F "required_status_checks[checks][][context]=gate / report"
   ```

## Verification

1. **Read-only checks** (before deploying):
   ```bash
   # Confirm Dodge uploads to code-scanning API
   gh api repos/gdcorp-im/{repo}/code-scanning/analyses?tool_name=Semgrep%20OSS | jq '.[].ref'
   
   # Confirm dependency graph is on
   gh api repos/gdcorp-im/{repo}/dependency-graph/compare/main...main
   ```

2. **Throwaway test PRs** (after deploying to one repo):
   - **(a) Clean PR:** expect ✅ comment, check passes.
   - **(b) Vulnerable dep:** add `lodash@4.17.11` (known high CVE), expect ❌ table row, check fails.
   - **(c) Semgrep trigger:** add `eval(req.query.x)` line, expect Semgrep row, check fails.
   - Push a fix to (b) and confirm the same comment updates to "✅ resolved" (not a new comment).

3. **Fallback path:** set `dodge_wait_minutes: 0` on a test run and confirm the CLI path runs and reports `source: cli`.

## Pre-requisites

- **GitHub Advanced Security** and **Dependabot alerts** must be enabled (on by default for most repos).
- **Dependency graph** must be enabled (check `security_and_analysis.dependency_graph` via API if uncertain).
- **gd-dodge app** must be installed (org-wide; already running on all target repos).
- **Self-hosted runners** must have network access to `semgrep.dev` (for the CLI fallback). If blocked, vendor a rules file into this repo and point `semgrep_fallback_config` at it.

## Limitations

- **Existing alerts** are not surfaced in the comment or blocking logic. The gate scopes to *new* issues introduced by the PR.
- **Semgrep CLI fallback** uses public rules (`p/default` by default), not GoDaddy's internal `godaddy.*` ruleset, so results can differ.
- **Large monorepos:** `dependency-review-action` reads all lockfiles; for marketing-cds's 10 packages, this is fine. For 50+, consider splitting into per-package jobs.
- **Private Artifactory PyPI:** the CLI fallback installs `semgrep==1.178.0` from Artifactory via JFrog OIDC. If the package isn't mirrored, the install fails and the fallback reports zero findings.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Check never starts | Workflow not in `.github/workflows/` or permissions missing | Verify caller YAML, check branch/PR settings |
| `deps` job fails with 403 | Dependency graph disabled or API access issue | Enable in repo settings |
| `semgrep` job waits 15min then reports zero findings | Dodge not uploading to code-scanning API, and fallback also failed | Check Dodge app status, confirm PyPI access |
| Comment not posted | `pull-requests: write` missing or PR from fork | Add permission; forks cannot write comments from workflows |
| Check passes but should fail | `block: false` or thresholds too high | Confirm `block: true` and thresholds match your policy |
